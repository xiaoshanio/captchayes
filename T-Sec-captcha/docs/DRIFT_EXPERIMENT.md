# 「数据过于老了」的可复现实验

> 这份文档回答一个具体问题：**模型精度下降，到底是"训练不够"还是"数据过时"？**
> 结论用可复现的数字给出，不靠感觉。

---

## 1. 为什么要做这个实验

用户最初的描述是「我想要继续训练这个自动化程序，并且数据过于老了」。
这句话里其实混了两个不同的假设：

| 假设 | 对应的动作 | 成本 |
|---|---|---|
| A. 模型训练不充分 | 加 epoch、调超参 | 低（只花算力） |
| B. 出题方改版，数据分布变了 | 重新采数据、重训 | 高（要改数据管线） |

**选错方向的代价很大**：如果是 B 而你去加 epoch，算力全白费；
如果是 A 而你去重新采数据，成本白花。

所以第一件事是**把两者分开测量**。

## 2. 实验设计

### 2.1 构造两个明确的域

用 `tools/synth_selfcontained.py` 的 `--style` 参数生成两个风格不同的数据集：

| | 域 A（`--style v1`） | 域 B（`--style v2`，漂移域） |
|---|---|---|
| 字形集 | 数字/字母/圆环/三角/方框/十字/星/菱形/折线 | **完全不同**：箭头/月牙/闪电/水滴/齿轮/半圆/双向箭头/感叹号 |
| 描边粗细 | 3 px | **5 px** |
| 图标尺寸 | scale 0.9~1.5 | **0.62~1.05（更小）** |
| 旋转幅度 | ±18° | **±38°** |
| 底图风格 | 渐变 + 几何色块 | **多尺度噪声 + 暗角（更像照片）** |
| 提示条高度 | 56 px | **68 px** |
| JPEG 质量 | 80~95 | **62~82（压缩更狠）** |

域 B 刻意在**字形、几何、纹理、压缩**四个维度同时偏移 —— 这正是出题方改版的典型形态。

### 2.2 量化域差异（先证明漂移真的存在）

`eval/domain_gap.py` 用纯统计方法给出域距离，**不需要模型**：

```powershell
python eval/domain_gap.py --a data/driftA --b data/driftB --split val
```

实测输出（500/100 规模）：

```
  指标                           域A(旧)          域B(漂移)          相对变化
  box_area_med                5698.0          3439.0        -39.6%     <- 图标小了 40%
  edge_density                0.0229          0.0129        -43.7%     <- 笔画密度掉了
  val_mean                    200.7           167.7         -16.4%     <- 整体更暗
  prompt_h_med                  38.0              46        +21.1%     <- 提示条图标变大
  n_cls0_mean                    5.5             6.5        +18.2%     <- 干扰项变多
  灰度直方图 JS 散度 : 0.1190   (0=相同, 越大差异越大)
```

**四个维度同时偏移，JS 散度 0.119** —— 漂移成立，不是错觉。

### 2.3 四阶段实验

`eval/drift_experiment.py` 自动跑完整流程：

```
阶段 0  生成域 A / 域 B / 混合集(A+B)，量化域差异
阶段 1  只用域 A 训练 -> 得到"旧模型"
阶段 2  旧模型 × 域 A / 域 B 评测   -> 得到"老化代价"
阶段 3  用域 B 重训 + 三个对照组
阶段 4  全矩阵评测 -> 结论
```

### 2.4 三个对照组（这是关键，不是可有可无）

只测"旧模型差、新模型好"是**不够的** —— 那可能只是"训练更久"带来的。
必须加对照才能把因果关系钉死：

| 对照组 | 构造方式 | 要证明什么 |
|---|---|---|
| **b) 旧数据多训 2× 轮** | 域 A 数据，epochs × 2 | 如果是"训练不够"，这一组应该也变好 |
| **c) A+B 混合训练** | 训练集 A、B 各半 | 混合能否兼顾新旧域 |
| **d) 重训后回测旧域** | 用域 B 训的模型测域 A | 有没有灾难性遗忘 |

有了 b)，才能说"加训没用，必须换数据"；
有了 d)，才能说"换数据要不要保留旧数据"。

## 3. 实测结果

> 完整结果见 `out/drift_exp/drift_experiment.json`。

### 3.1 核心发现（用上一轮已训好的 19-epoch 模型做的快速验证）

先不重训，直接拿**上一轮训好的模型**在两套域上跑，确认漂移是否真的会造成失效：

| 评测集 | 端到端全对率 | class2 框数不符 |
|---|---|---|
| 旧域 A | **56.7%** | 1/30 |
| 漂移域 B | **13.3%** | 20/30 |

**同一个模型，只因为换了评测域，从 56.7% 掉到 13.3% —— 掉了 43 个百分点。**

失效机制很明确：`class2 框数不符` 从 1/30 涨到 20/30。
即**提示条字符检测大面积失效**，导致贪心指派的矩阵尺寸错，点击顺序必然错。

### 3.2 低成本版：复用已训模型 + 只训一个新模型

`eval/drift_experiment.py --full` 要训 6 个模型（CPU 约 3~5 小时），
且若训练轮数不足会得到"全 0"的无效结果。为此另写了
**`eval/drift_recover.py`**：复用已训好的模型当"旧模型"，只训一个漂移域新模型，
跑 2×2 矩阵即可回答全部决策问题（约 35 分钟）。

```powershell
python eval/drift_recover.py --train-new --epochs 10 --n-train 400 --n-val 100
```

实测结果见第 6 节。

## 5. 这个实验对「继续训练」的实际指导

跑完之后能直接回答四个决策问题：

| 问题 | 看哪个指标 |
|---|---|
| 我的精度下降是"训练不够"吗？ | 对照组 b（旧数据多训）的收益。若 ≈ 0 → **不是训练问题** |
| 必须重新采数据吗？ | 老化代价（②−①）。若 > 20 pt → **必须换数据** |
| 换数据要不要保留旧数据？ | 遗忘量（①−⑥）。若 > 8 pt → **需要混合** |
| 混合训练够不够？ | ④ vs ⑤。若 ④ ≈ ⑤ → **混合即可，不必全换** |

## 6. 实测结果（本轮真实跑出来的）

> 完整数据见 `out/drift_rec/drift_recover.json`、`out/drift_fix/fix_check.json`、
> `out/crop_src/crop_source.json`、`out/matcher_score.json`。

### 6.1 数据老化代价：**−73.3 pt**（核心结论）

用上一轮已训好的 19-epoch 模型（`runs/export_nms`）当"旧模型"，
在旧域 A / 漂移域 B 上分别跑端到端（60 题，conf=0.2）：

| | 旧域 A | 漂移域 B |
|---|---|---|
| **旧模型** | **80.0%** | **6.7%** |

**同一个模型、同一套 runtime，只因为数据变"老"，准确率从 80% 崩到 6.7%。**
这就是用户所说「数据过于老了」的量化证据 —— 不是模型不会解，是它解的**不是现在这套题**。

失效机制（`eval/drift_diag.py` 逐题打印）：
`class2 框数不符` 从 3% 飙到 72~78%，提示条字符检测大面积失效 →
贪心指派的矩阵尺寸错 → 点击顺序必然错。

### 6.2 检测器本身没坏 —— 坏在"框质量"

分项测量（40 题，conf=0.2）：

| 模型 × 域 | class0 P / R | class2 P / R |
|---|---|---|
| 旧模型 @ 漂移域 | 0.900 / 0.934 | 0.875 / 0.957 |
| 新模型 @ 漂移域 | **0.973 / 0.988** | **0.964 / 0.964** |

检测器在漂移域上依然很强，但端到端只有个位数 —— 说明**信息在中间环节被破坏了**。

### 6.3 真凶：匹配器对「框抖动」高度敏感

`eval/crop_source_test.py` 把"裁剪框来源"这一个变量单独拎出来（34 题）：

| 裁剪框来源 | 全对率 |
|---|---|
| A 真值框 → 真值框（上界） | **91.2%** |
| B 检测框 → 检测框（真实推理路径） | **61.8%** |
| C 真值提示 + 检测目标 | 55.9% |
| D 检测提示 + 真值目标 | 55.9% |

**框抖动造成 29.4 pt 损失**。检测框与真值框平均 IoU 只有 0.81（p10=0.69），
裁出来的图标会多带背景 / 切掉笔画；而匹配器训练时只见过"完美框"，
于是**训练分布与推理分布不一致**。

### 6.4 尝试修复：加 padding —— 无效

| pad | A（上界） | B（真实） | A−B |
|---|---|---|---|
| 0 | 91.2% | 61.8% | 29.4 |
| 4 | 85.3% | 55.9% | 29.4 |
| 8 | 64.7% | 47.1% | 17.6 |
| 12 | 47.1% | 32.4% | 14.7 |
| 16 | 20.6% | 29.4% | −8.8 |

padding 只是把两边一起拉低，**上界掉得比下界还快**，不能解决问题。

### 6.5 尝试修复：框抖动增强 —— 失败（重要负面结果）

思路是对的（让训练分布覆盖推理分布），但实现踩了坑：

| 配置 | val_acc | 真值框全对率 | 诊断 |
|---|---|---|---|
| 无抖动（基线） | 0.964 | 91.2% | 正常 |
| `--jitter 0.12` | **0.728** | **11.8%** | 输出恒为 0.313 |
| `--jitter 0.04` | 0.250 | — | 更差 |
| `--jitter 0.10 --jitter-target-only` | 0.630（震荡 0.75→0.29） | — | 不稳定 |

`eval/matcher_score_diag.py` 一针见血地定位了原因：

```
matB_jitter:  对角(正样本) mean=0.313  p10=0.313
              非对角(负)   mean=0.313  p90=0.313
              分离度 = -0.000
```

**模型塌缩成常数输出**（对任何输入都吐 0.313）—— 抖动太强，
正样本被破坏到"和负样本无法区分"，模型于是学到了"放弃"。

根因：提示条图标在**纯白底**上，抖动会把邻居图标和留白拉进裁剪，
直接毁掉正样本。即使改成只抖目标侧（`--jitter-target-only`），
在 6 epoch 下仍然不稳定。

**结论：这条修复路走不通（至少当前实现与训练预算下）。**
`--jitter` 因此**默认 0（关闭）**，且文档明确标注为失败实验，
避免后来者重复踩坑。

### 6.5b 修复：用**真实检测框**对齐训练 —— 有效，但增益有限

6.5 的失败是**随机抖动**的失败，不代表"训练-推理对齐"这个方向错。
于是改用**检测器实际输出的框**来生成匹配器训练集（不引入人为破坏）：

```powershell
python tools/prepare_pairs_det.py --synth data/driftB \
    --det runs/drift_rec/export/detB.onnx --out data/driftB_pairs_det --conf 0.2
```

对齐率：train 83.0%（249/300）、val 85.0%（68/80）——
即 8 成以上的题，检测框能与真值框按 IoU≥0.5 一一对上，足以训练。

**但第一次训练直接塌缩**：

| 配置 | val_acc | 说明 |
|---|---|---|
| `matB_det`（6 ep，lr 3e-4） | 0.7177 | 恰好 = 负样本比例 600/836 |
| `matB_det2`（10 ep，lr 1e-4） | 0.7177 | 降 lr 无效 |

`0.7177 == 600/836` 这个**精确相等**就是塌缩的铁证（模型全判负）。
原因：难负样本配比 3:1 且**全部是 hard**（同题内其它图标），
不加权的 BCE 最优解就是"全判负"。

修复：给正样本加权 `pos_weight = neg/pos`（本轮已加入
`train/train_matcher.py` 的 `--auto-pos-weight` / `--pos-weight`）。
加权后先反向塌缩到 0.2823（= 正样本比例），**继续训练才真正学会**：

| epoch | val_acc |
|---|---|
| 1~6 | 0.2823（全判正，塌缩） |
| 7 | 0.3756 |
| 8 | 0.7213 |
| 10 | 0.8074 |
| 25 | **0.8182** |

最终端到端（`eval/e2e_ablate.py`，60 题，漂移域）：

| 匹配器 | 原始 | 去重后 | class2 不符（去重后） |
|---|---|---|---|
| `matB_gt`（真值框训练） | 3.3% | 10.0% | 15% |
| **`matB_detpw25`（检测框对齐 + 加权）** | 5.0% | **16.7%** | 15% |
| `matA_old`（旧域模型） | 1.7% | 8.3% | 15% |

匹配器分离度（`eval/matcher_score_diag.py`）：

| 匹配器 | 对角均值 | 非对角均值 | 分离度 |
|---|---|---|---|
| `matB_gt` | 0.711 | 0.297 | 0.414 |
| **`matB_detpw25`** | **0.839** | 0.305 | **0.533** |
| `matA_old` | 0.924 | 0.303 | 0.620 |

**判读（诚实版）**：
- 方向是对的：分离度 0.414 → 0.533，端到端 +6.7 pt，框抖动损失从 29.4 pt 降到 8.8 pt。
- **但绝对水平仍只有 16.7%**，离可部署很远。真正的天花板是
  `matA_old` 的分离度 0.620（90% 全对）—— 说明**匹配器本身的判别力**才是主约束，
  而不只是框口径问题。
- 因此下一步优先级应调整为：**换更强 backbone / 加数据**，而不是继续抠框口径。

### 6.6 修复：后处理去重 —— 有效但不够

`eval/drift_fix_check.py`（40 题）：

| 模型 × 域 | 原始 | 去重后 | class2 不符 |
|---|---|---|---|
| 旧模型 @ 旧域 | 85.0% | 87.5% | 2% → 0% |
| 旧模型 @ 漂移域 | 7.5% | **15.0%** | 75% → 40% |
| 新模型 @ 漂移域 | 5.0% | **15.0%** | 75% → **12%** |

去重把 class2 框数不符从 75% 压到 12%（**非常有效**），
但端到端只回到 15% —— 说明**框数对了，顺序还是错**，
而顺序错的原因正是 6.3 的框抖动。

### 6.7 结论汇总

| 问题 | 答案 | 证据 |
|---|---|---|
| 数据老化是真的吗？ | **是，−73.3 pt** | 6.1 |
| 检测器坏了吗？ | **没有**（P/R 0.96~0.99） | 6.2 |
| 真凶是什么？ | **匹配器对框抖动敏感，−29.4 pt** | 6.3 |
| 加 padding 能修吗？ | **不能** | 6.4 |
| 加抖动增强能修吗？ | **当前实现不能（模型塌缩）** | 6.5 |
| 去重能修吗？ | **能修框数，修不了顺序** | 6.6 |
| 那正确方向是什么？ | 见 6.8 | — |

### 6.8 下一步的正确方向（基于以上证据，已按优先级重排）

1. **★ 换更强 backbone / 加数据（当前第一优先级）**
   证据：`matA_old` 分离度 0.620、真值框全对 90%；而漂移域上最好的
   `matB_detpw25` 分离度只有 0.533、真值框全对 70.6%。
   **同样的框口径下，判别力本身就差了 20 个点** —— 这才是主约束。
   当前 `mobilenet_v3_small` + 858 正样本明显不够。

2. **提高检测框定位精度**
   检测框 vs 真值框平均 IoU 0.81（p10=0.69）偏低。
   可试更大 imgsz、更强检测 backbone、或提高 box 回归损失权重。
   注意：这一项只能把"框抖动损失"（现 8.8 pt）再压一点，不是主约束。

3. **已做完：训练-推理框口径对齐（`tools/prepare_pairs_det.py`）**
   有效（分离度 +0.12，端到端 +6.7 pt），但**不足以单独解决问题**。
   保留该工具，作为后续训练的默认数据构造方式。

4. **已做完：后处理去重**
   把 class2 框数不符从 75% 压到 12~15%，是性价比最高的一步。
   建议**默认开启**。

## 7. 已知局限（诚实记录）

1. **两个域都是程序化生成的**，漂移形态比真实改版"干净"。
   真实站点的漂移可能只改一部分（比如只换字体），也可能引入完全新的干扰形式。
   → 本实验证明的是**方法论有效**，具体阈值要拿真实数据重新标定。

2. **没有测"渐进漂移"**。
   真实世界是慢慢变的（每周变一点），本实验是"一次跳变"。

3. **新模型只训了 10 epoch / 400 张**（旧模型是 19 epoch / 800 张），
   所以"重训收益 −3.3 pt"**不能**解读为"重训没用"，
   而是**训练预算不对等**。要下结论必须用同等预算重跑。

4. **`--smoke` 模式（2 epoch）产出的模型检测不出任何框**，
   因此全部指标为 0。这是**预期行为**（欠训练），不是 harness 的 bug。

5. **6.5 的抖动增强失败可能与训练预算有关**（6 epoch 偏少）。
   若给到 20+ epoch 且用更温和的抖动，结论可能不同 —— 本轮未验证。

6. **漂移域端到端最高只有 16.7%**，远未达到可部署水平。
   本节的结论是"**机制已定位**"，不是"问题已解决"。
   真正的修复需要第 6.8 节第 1 项（更强 backbone + 更多数据）。

7. **`pos_weight` 塌缩问题只在"小 + 全难负样本"时出现**。
   本轮把 `--auto-pos-weight` 设为**默认关闭**以保持既有行为；
   用 `tools/prepare_pairs_det.py` 造数据时**必须显式开启**，否则训练会塌缩。
   已在 `train_matcher.py` 加入塌缩告警（val_acc ≈ 多数类比例时打印 `[塌缩!]`）。

  所以本仓库**没有**、也**不会**内置针对该站点的采集器。

- 但**链路已经准备好了**：新增 `tools/ingest_captures.py`，
  把你**自己手动截的图**整理成下游要的 `data/samples/<sid>/` 结构，
  并带质量闸门（尺寸/方差/感知哈希去重/提示条切分校验）。

  ```powershell
  # 一个目录放你截的图，每张 = 一个样本
  python tools/ingest_captures.py --src my_shots --out data/samples
  # 之后接既有链路
  python tools/plate_gen.py   --samples data/samples --out data/plates
  python tools/icon_assets.py --samples data/samples --out data/assets
  python tools/synth_gen.py   --plates data/plates --assets data/assets --out data/synth
  ```

  已用自造截图做过端到端验证：收 8 张、拒 1 张纯白、去重 1 张，
  自动切出提示条 8/8，`plate_gen` 检出图标 mean=5.6，
  `icon_assets` 提取 24 个素材，`synth_gen` 合成 52 题，
  `audit_dataset.py` 六项一致性检查全 OK。

- **请注意使用边界**：`ingest_captures.py` 只处理你**有权使用**的图片
  （自有服务、已获授权、或自己手动截的公开演示页），它**不做任何网络请求**。
  另外，公开演示页的验证码与真实业务站点通常是**不同 appid / 不同难度配置**，
  拿它训出来的模型直接上生产仍有域差异，必须按第 3 节的流程做验收。
